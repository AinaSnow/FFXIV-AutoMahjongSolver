## 2. 顺序与验收原则

先统一旧归档审计和回放，补 v7 回归与构建门禁，再定位首摸超时。半庄离线验证可立即进行，不依赖整个调度重构。之后按证据开放协议、小步重构、独立评测东风终局特征，最后考虑训练。

每批独立提交；记录代码版本、输入哈希、工具/模型哈希、命令和结果。原始私人牌谱与产物留在忽略目录 `artifacts/`，脱敏总结进入文档。没有出现的场景标记“证据不足”，不以随机十场未复现作为通过。普通测试不能创建或改写 golden。

## 3. P0：旧数据回归与稳定性收口

1. 使用 `tools/audit_live_archives.py` 汇总归档，复用生产 `Mahjong.PacketReplay` 解码器批量回放已有抓包。每个输入均有成功、失败或证据不足记录；不静默跳过损坏、缺尾或空输入。
2. 为东四转南一、南二连庄、四种自身座位、无效场风/局号及东场限定门禁补测试；用实际完整半庄验证当前 v7，而非只看历史 v6 日志。
3. 首摸超时分段测量：子进程创建、首次写入、首次确认、依赖导入、模型加载、设备初始化、首次推理。已有日志的首次确认约 11.8–13 秒、正常推理约 50–80 ms，指向首次确认前的准备阶段，但不能据此断言具体模块。增加 runner 单调时钟诊断并离线重现。保留现有和牌/鸣牌/出牌时限，预热必须另有生命周期与跨局隔离测试。
4. 统一异常清单：超时、失败、缺失执行结果、状态变化、服务端确认、取消和外部输入分开统计。归档摘要只代表已记录的计数，不能替代原始动作闭环核对。
5. 将卡住、瞬时 Ron、Ron/Chi 同屏、暗杠后立直、自家加杠、负分结算、杠弹窗取消逐项建立证据矩阵。先复用现有样本；确实缺事件时才补采集。
6. 修复役满宝牌审计、完善和牌/放铳 unknown 标签；无法确定的不强行训练化。修订 architecture、dispatch-protocol 等旧文档时保留历史日期。
7. 本地完整逻辑/插件测试与 Release 构建通过；补 CI 手动入口。推送后另核对当前提交的 Windows 和逻辑 job，未运行不得写“远端通过”。

验收：具体历史故障有回归断言和回放证据；未覆盖项明确保留；首摸耗时有阶段定位。该阶段不宣称胜率提高。

## 4. P1：逐步整理调度与线程归属

- 先提取等待决策、待确认动作和终局确认等独立状态，建立 `Step(state, snapshot, now)`；每次只迁移一条已覆盖路径。
- 统一请求、派发、状态变化、服务端确认、超时/拒绝闭环；多步动作保留父动作 ID。不能把派发返回 Ok 当作成功。
- golden 只固定已确认正确的行为；已知错误应先补失败测试，再修正期望。每次变更核验取消、卸载、跨局旧回调和重复派发。
- `MortalProcessClient` 的后台读取把响应入队，由 framework 的 Poll 分发回调（续批复查更正）。保持并验证该所有权，再决定锁是否冗余，不能只改注释就删锁。
- 按职责拆分进程监管、事件隔离、挂起反应、推荐缓存与统计。构造/释放逐步转入服务容器，异常构造需要撤销已注册事件。
- 成功标准是线程归属明确、无跨局动作、回放/恢复检查通过；不使用“文件少于 500 行”或完全照搬错误行为作验收。

## 5. P2：协议、规则及半庄

1. 立即离线回放已有半庄：真实场风、局号、连庄、供托和座位。解码通过与模型接收通过分别报告；均不自动开放线上。
2. 半庄上线还须确认比赛模式/长度、起始庄家、局间/终局边界和恢复隔离，列出 FF14 与 libriichi 规则差异。全局场风不是比赛模式的充分证明，东风仍可能有特殊结束条件。

## 6. P3：策略与评测

### 指标及实验设计

主指标为平均名次，并报告一位率、前二率、四位率、和牌/放铳与得分；Rating 有直接观测时单列。离线同模型三家对手的平均 2.5 不能外推到 FF14 对手池。

- 一名候选对固定三名对手；相同随机种子轮换四座，基线重复相同组合，按种子组计算配对区间。
- 训练、开发与最终验收种子严格分离。dev100 用于筛选；正式默认 1000 组/8000 场。是否扩大到 2000 组，要在看验收结果之前依据开发集方差和目标检验功效预先确定。
- 95% 置信水平与检验功效不是同一概念，不用“2000 场保证 95% 检出”之类表述。
- 晋级门槛保持：平均名次差 ≤ -0.03 且 95% 区间上界 < 0；四位率差 95% 区间上界 ≤ +0.01；没有非法动作、恢复或重复派发回归。未过门槛保持实验选项。
- 固定模型/引擎/规则/种子/GPU 批大小，并分别报告不同对手池。Markdown 已包含四位率区间，本轮补齐控制台输出。
- Doman 引擎尚未对齐的多赢家本场/供托、包牌等必须继续列在报告；实验规则模式不能认证线上强度。

### 执行异常与棋力分开

审计工具输出可观察异常、局面/动作关联和证据等级，按严重性及频率安排修复。没有完整反事实模型时，点数/名次损失为 unknown/null；真实后续牌谱不能回答“换个动作最终多赢多少”。

不再预先承诺平均名次改善 0.02–0.08，也不把非 Mortal 来源统算为约 10% 兜底。微调是可选路径之一，当前先消除输入、同步和执行问题。
