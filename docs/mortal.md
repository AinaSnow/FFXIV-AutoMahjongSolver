# Mortal、协议与客户端兼容性

## 设置

在设置页填写 WSL distribution、Mortal working directory（Linux 路径）及 Python executable（如 `./venv/bin/python`）。原 Mortal 目录需已有可用的 config、libriichi、torch 和模型。此次继续加载原配置指向的权重，没有训练或替换 Mortal 模型。

插件包中的 `mortal_runner.py` 在该工作目录运行。它通过原 Mortal 模块构建引擎，并给每条输入返回确认。不要替换成只输出动作的旧 runner，否则 session/hand/sequence 校验会拒绝输出。

插件主线程只入队输入和消费回调；启动、输入输出、终止和退出等待在后台。有界输入队列满、错误确认、进程退出会使会话失效。完整事件历史可重播；丢包或无法安全解释事件则隔离当前手局，等待下一局。重播事件 `can_act=false`，不能补执行历史动作。离桌或切换配置取消延迟动作。

已有样本优先通过 [离线 Mortal 回放](offline-mortal-replay.md) 定位解码和模型问题，无需重复随机对局。原采集操作记录见 [2026.09.15 采集说明](capture-20260915.md)。

## 当前有限试用

国际服 `2026.09.15.0000.0000 / Emj` 可选择默认关闭的 **Mortal limited trial (2026.09.15 / Emj)**，同时保留 Use Mortal for live decisions。先热重载原 dev 插件，再启用开关；已有模型和自动操作设置不用重填。建议在进桌前开启，中途开启则可能等待下一小局。

只在观察到完整开局、东场、起手总分确认无留存供托的限定下接入。未支持的杠、状态缺失或网络故障会让当前小局交回内置策略，下一小局重新检查。无需为开发连续匹配或刻意制造特殊牌型。完整 profile 仍为未验证，EmjL 与其他客户端版本不通过此试用开关。详见 [证据、保护与限制](reviews/20260924-mortal-limited-trial.md)。该版本尚未现场验收，不宣称提高胜率。

## 协议证据门禁

`data/protocols/` 按精确游戏版本与实际 addon 名登记 opcode/载荷长度。协议身份来自生命周期/轮询观测的窗口名，不能使用会随手牌加载切换的内存布局别名（例如实际 Emj 窗口也可能使用 EmjL 布局）。归档分别记录 client_variant 与 ui_layout。运行时从游戏目录 `ffxivgame.ver` 匹配版本；当前 `unverified-template.json`是未验证模板，不能自动启用正式协议网络 Hook。独立的 [自动调试录包](auto-packet-logger.md) 可显式开启，只保存原始证据，不参与推理。UI 的 Emj/EmjL 布局与网络协议验证是两套独立能力。

未验证且未显式开启匹配范围的有限试用时，Mortal 显示明确降级原因，内置策略继续使用已有 UI 读取。归约器能接受完整 MJAI 杠、宝牌、本场和供托事件，不意味着现有游戏报文解码器已经能够产出这些事件。当前没有可证明完整性的协议档案。

将新协议标为完整验证前必须完成：

1. 在已知游戏版本、区域/客户端变体的受控桌局采集原始载荷与时间、对应 UI 状态、预期事件。采集必须在显式开发工具中进行；不能通过把 `Verified` 改为 true 绕过验证。
2. 覆盖四种自身座位、庄家轮转、场风/局号、本场供托、立直、三种杠及多个杠、杠后宝牌和补牌。确认字段意义与长度，并给未知字段留空或清除观测标记。
3. 补齐游戏报文解码与自杠服务端回执匹配，确保同一杠只产生一次事件。已有临时自杠补发逻辑还不能替代这一步。
4. 将连续捕获整理为回放测试，证明事件/UI 合并一致、无跨手局动作；证据路径与客户端版本一起登记。禁止把固定 0/false 当已观测值。

原始内存或数据包可能包含玩家信息，整理回放前删除无关字段；完整本地采集留在忽略目录中。此项目不再上传遥测。

## 归档与故障定位

`match-archives/<session>/games/` 保存已有兼容游戏日志，`packets.ndjson` 保存完整验证或有限试用准入时捕获的数据包，`summary.json` 保存本地摘要；`managed-complete.json` 表示归档写入流程结束，其 `incomplete` 仍可为 true。无结束标记的旧目录不会被自动清理。

排查先查看实际降级原因和 session/hand/sequence，再比对 snapshot revision、decision 和 action。回放一致率衡量状态与执行回归，不能替代对战名次。Mortal 未返回候选分布时，UI 显示无候选数据，不填入内置策略分数。

## 2026-09-24 接收后端迁移

正式接收与调试录包共用 [Deucalion 后端](auto-packet-logger.md)，不再在 OnReceivePacket 入口按固定长度复制游戏内存。原始数据必须通过管道握手和长度校验，再匹配已验证或用户显式开启有限试用的精确客户端版本/变体 profile，且载荷长度必须精确一致。未准入 profile、未知 opcode 和长度不匹配的数据不会喂给 MJAI；不再使用历史测试 opcode 表作为运行回退。

Mortal 的启用条件增加传输已连接。连接失效时停止现有模型会话；捕获丢失仍走原有隔离/下一局同步逻辑。调试开关只控制文件录制；已验证协议存在或有限试用开启且版本有对应证据时，消费者独立保持接收。试用范围由独立标记准入，不将候选 profile 的 verified 改为 true。
