# 麻将决策与棋力改进计划（2026-10-05）

状态：自然终盘成对续打已完成：400 场新自然对局、64 个根、192 条分支结果；未达到预登记继续门槛，本候选停止，不扩量或替换线上模型。详见[最新结果](reviews/20261006-natural-endgame-results.md)。工程事项继续暂缓。

## 1. 决策

当前线上自动对局的麻将策略统一交给 Mortal；离线允许评估其他完整决策引擎，只有实际对照和独立验收支持时才讨论替换。本地插件负责读取、同步、校验和执行，不再维护第二套会替 Mortal 改选动作的策略。

停止将“继续采集、增加校验、优化本地兜底”作为棋力改善的主线。保留直接防止错误操作的最小检查；后续棋力工作围绕决策模型、决策引擎及实际对照结果展开。

方案讨论时仅修改文档；现已按第 5 节及后续预登记完成A/B/C隔离微调，尚无足够提升证据，也不承诺撤掉本地兜底就提高胜率。最近两场合计 11 手没有我方和牌，已记录的本地兜底和超时均为 0；撤掉兜底不能据此解释这两场失利。

## 2. 自动决策链的调整

目标链路：

游戏局面 → Mortal 输入 → Mortal 最终合法动作 → 插件执行

### 移出自动策略链

- 内置策略的舍牌、吃碰杠和立直选择。
- Mortal 等待、超时、异常或隔离时自动调用本地策略选牌。
- Mortal 明确选择跳过后，被本地启发式改成立直、鸣牌或和牌。
- 使用本地候选评分代替 Mortal 的建议，或者让提示与执行来自不同策略。
- 插件在模型决策之前，以本地策略选择的和牌覆盖模型判断。

最后一项必须核对现有 terminal win guard 的路径。合法和牌检测可以保留，但“当前可以和牌”不等于“插件应覆盖 Mortal 决策并立即和牌”。Mortal 自身的规则辅助层是否启用，应作为固定、可追溯的模型运行设置，并在模拟和实战保持一致。

首先断开本地策略在自动对局中的调用，不进行大范围代码删除或重构。若其他独立模式仍使用它，不连带破坏这些模式；但停止把它作为当前棋力研发对象。清理无调用代码不作为本轮前置任务。

### 保留的本地职责

- 手牌、公开事件和座位等输入的正确读取与同步。
- 合法动作、红牌身份及当前可点击目标的校验。
- 决策属于当前手局和局面版本的检查。
- 离桌、切换模式、关闭自动操作时取消未执行动作。
- 自动排队、进场确认、局间确认和离场等界面流程。
- 对服务端已经确认关闭的窗口进行确定性界面恢复；不得借恢复流程创造新的麻将策略选择。

这些功能不判断“哪张牌更好”，也不能静默改写 Mortal 的动作。若候选非法，拒绝执行并记录原因，而不是自行挑另一张牌。

## 3. Mortal 失败时的明确行为

| 情况 | 行为 |
|---|---|
| 收到当前局面的合法 Mortal 动作 | 按原动作执行，保留动作来源 |
| Mortal 返回合法的跳过/none | 尊重该选择，不转调用本地策略 |
| 正常推理尚未到截止时间 | 等待，保持既有超时预算 |
| 超时、进程异常、局面不完整或当前手局被隔离 | 不再替 Mortal 选牌；停止该次自动决策并明确显示原因 |
| 旧进程、旧手局或旧局面结果到达 | 丢弃，不执行 |
| 后台进程完成恢复 | 只有重新满足当前局面和同步门禁后才恢复自动决策 |

代价必须明确：纯 Mortal 模式在故障时不会由插件主动挑一张牌补上，游戏倒计时可能触发游戏自己的默认行为，也可能需要用户接管。不能将这种情况记录为 Mortal 成功决策，不能称为插件已安全完成出牌。

恢复过程不得为了维持自动运行而接受不完整输入。保留现有可验证的重放/下一局恢复机制，不在本轮另建复杂恢复框架。

## 4. 一次有限的实施与验收

只做与本次决策链变更直接相关的回归：

1. 当前合法 Mortal 动作能够原样执行，红牌不混淆。
2. Mortal 跳过时，本地策略和和牌保护不改选。
3. 超时、异常和状态不完整时不调用本地策略，也不执行旧结果。
4. 离桌或换局后，待执行动作被取消。
5. 必要的进场、确认和离场流程不因移除策略兜底而失效。

优先复用已有回放和测试，不要求用户额外随机打牌补样本；确实缺少某条关键路径时才提出具体需求。既有适用测试仍须通过，但不以测试总数增加作为交付价值。

本轮交付应明确回答：
- 自动麻将动作是否全部来自 Mortal；
- 还有哪些路径会改选，是否已移除或明确限定；
- 模型失败时用户看到什么、游戏实际发生什么。

这些是行为一致性验收，不是棋力提升证明。

## 5. 模型主线：基于现有 Mortal 权重做 FF14 定向微调

### 5.1 目标与范围

在现有模型能力上训练新权重，让策略更适合 FF14 的比赛长度和排名目标。用户关心前二率和长期上分能力；单局和牌率不能代替这两个目标。首先针对常玩的东风战训练与验收，半庄单独报告，不将东风收益外推到半庄。

先固定当前权重、规则适配与 Mortal 运行设置，使模拟和实战的决策路径一致。复用已有模拟、导出和评测入口，只补训练不可缺少的部分。每轮必须实际产出候选权重及对照结果，不把新增采集工具、样本数量或测试数量作为棋力交付。

本阶段不从零训练大模型，不增加外部记牌器，不做多模型投票、复杂搜索或内置策略增强。线上仍只有一个决策来源。

### 5.2 数据与对手

- 主数据来自经过规则适配的完整模拟对局，记录规则版本、模型哈希、对手、随机种子、比赛长度和终局成绩。
- 真实 FF14 记录用于检查模拟与实战差异，并在信息及标签足够时补充训练；不要求用户继续手动刷局。无法重建完整事件或结算的记录不强行生成训练标签。
- 训练输入只包含当时该玩家可见的信息。完整终局结果可作为收益标签，但不能把对手暗牌、未来摸牌或未来事件混入输入。
- 固定旧权重和有来源的不同模型组成训练对手池。首轮若只有一个可用模型，明确记录对手多样性不足，不用重复模型冒充不同风格。
- 保留赢局和输局，按完整对局去重与划分训练、开发和最终验收集合；同一牌山的轮换座位、重复轨迹和数据增强版本归入同一集合。
- 不能只复制旧模型动作。使用对局收益训练动作价值，并在模拟训练中安排受控探索；不在真实自动对局中随机试牌。旧策略离线数据的动作覆盖有限，不能指望单纯反复训练这些数据必然超越旧模型。

### 5.3 第一轮候选与训练目标

固定三个比较对象：

| 对象 | 参数更新 | 收益目标 |
|---|---|---|
| 基线 | 当前权重完全不更新 | 保持现有设置 |
| 候选 A | 冻结主体网络及 BatchNorm 统计，仅微调最后的动作评分层 | 平均名次方向，例如终局效用 [3, 1, -1, -3] |
| 候选 B | 与 A 相同，使用相同数据与训练预算 | 偏重前二，例如终局效用 [1, 1, 0, -0.25] |

数组依次对应第一至第四名，是首轮实验效用，不是 FF14 Rating 公式。B 对第四名增加代价，但不保证四位率不会变差，仍须实际验收。正式实验前固定数值，不依据最终验收结果反复调整。

首轮 A/B 尽量使用同一份固定离线训练集以比较目标差异；若后续加入随策略更新的自对战，单独作为下一轮实验，并记录数据分布变化。

复用 Mortal 的收益回归、离线保守约束及辅助名次训练路径。若使用 GRP 将终局效用分配到各手，须检查它在 FF14 东风数据上的适配，并用同一收益定义生成标签；仅改配置或只训练 GRP，不等于推理策略已经改变。缺少原优化器、辅助网络或 GRP 状态时，显式初始化或单独准备所需组件，不能宣称无缝恢复原训练。

冻结主体的同时冻结其归一化统计，保存独立优化器和训练状态；新权重不得覆盖线上基线。若输出层更新没有收益，不默认扩大网络更新范围。只有开发集证据支持下一轮假设时，才尝试解冻末段网络或增加比赛长度修正分支；不得伪造场风来表示东风终盘。

### 5.4 计算预算和停止条件

1. 先做一次短时吞吐测量，记录实际 GPU/显存、模拟局数每小时、训练决策数每秒和峰值显存，不预先承诺本机一天能训练出强模型。
2. 建议首轮总计算上限为 24 GPU 小时，包含试跑、数据生成、两个候选训练和开发比较；同时固定模拟场数及优化步数上限。根据试跑填写具体规模，再开始正式实验。该上限是计划建议，不是购买云算力的授权。
3. 训练前锁定数据清单、训练/开发种子、候选数、学习率方案和检查点选择规则。先冻结基线；开发阶段最多从 A/B 各选一个检查点比较，不无限扫描配置。
4. 预算结束必须报告候选权重、完成规模和结果。开发比较没有改善信号就结束本轮，说明是失败还是证据不足；不自动扩量或要求用户继续对局。
5. 只有开发胜出候选才进入独立正式验收。默认 1,000 个种子组，候选与基线各轮换四座，共 8,000 场；正式评测预算在启动前另行估算并锁定，不边看结果边增加样本。

### 5.5 交付与上线

必须交付：基线及候选权重哈希、可重复训练配置、数据与种子划分、硬件和实际耗时、逐场结果、配对置信区间、是否达到门槛的结论。

前二率是本轮重点业务指标，同时保留第 6 节的平均名次与四位率门槛。前二率改善以“候选减基线”的配对差值衡量；只有独立验收的 95% 区间下界大于 0，才宣称有前二率提升证据。未达到条件时保留实验权重，不替换线上默认模型。

模型候选、Mortal 内部规则辅助变更和插件执行修复分别比较。模拟通过后只需有限实战确认兼容和执行情况，不能用少量真实对局证明胜率提升，也不要求用户长期陪跑采样。

技术依据：[Mortal 固定版本训练代码](https://github.com/Equim-chan/Mortal/blob/0cff2b52982be5b1163aa9a62fb01f03ce91e0d2/mortal/train.py)、[收益计算](https://github.com/Equim-chan/Mortal/blob/0cff2b52982be5b1163aa9a62fb01f03ce91e0d2/mortal/reward_calculator.py)。上述微调、收益比较与冻结方案是本项目拟实施的实验，不是上游已经验证的 FF14 棋力结论。

## 6. 成绩和止损

- 主指标为平均名次，前二率和四位率单独报告。和牌率、放铳率和得分用于解释结果，不替代最终目标。
- 保留相同种子、轮换四座、候选与基线配对的比较。以种子组计算区间，不把四座或重复轨迹当独立样本。
- 相同模型对自身的前二率 50% 是对称对照结果，不能用于宣称真实玩家对局胜率。
- 候选默认替换门槛仍为平均名次改善至少 0.03 且差值 95% 区间上界小于 0，四位率差的区间上界不超过 +1 个百分点，并通过相关输入与执行回归。
- 没有前二率改善证据时，不宣传“更容易进前二”；模拟点数不等于 FF14 Rating。
- 正式候选必须在开发选择后冻结，再做独立验收；不反复抽种子直到显著。

纯 Mortal 决策链这一轮以完成有限的改动和上述五类检查为止，不扩展为无限工程治理。

后续若启动模型实验，事先固定候选、数据规模、种子和计算预算。时间盒结束仍无改善信号，就停止该方案并报告失败或证据不足，而不是用更多数据和测试掩盖结果。

当前没有足够证据推荐本项目为稳定上分工具。可以推荐其已验证的自动操作能力，棋力收益必须另有实测支持。

## 9. 候选C逐手价值收益结果（2026-10-05）

完成B决策分歧复盘，随后复用同一训练集，通过名次价值校准和四折交叉拟合生成逐手收益，训练一个候选C。拟合分数模型的留出排列NLL为2.424135，较固定参考降低7.62%；本轮GRU未胜出。主体及BatchNorm保持完全冻结。

C与B在同一批新开发种子1007000–1007099上分别对照原始基线，共1600物理对局。C平均名次2.5125、前二率50.50%、四位率25.25%；B本轮为2.5350、48.75%、25.25%。C相对基线平均名次差+0.0125，前二率差95%区间[-1.75, +2.75]个百分点。

价值预测校准改善未转化成达到门槛的决策收益，本轮停止，不进入正式验收，不扩量、不解冻、不替换线上权重。产物与逐场对照见[候选C结果与复现](reviews/20261005-doman-credit-C-results.md)。任何下一轮只围绕具体决策假设重新登记，不恢复工程事项。

## 10. 后续模型路线（A/B/C结果后的建议）

下一轮优先检验动作学习目标，再按证据考虑策略更新后的自对弈数据和模型表示。以下是后续路线。用户已要求继续推进，D已按[固定设计与预登记](reviews/20261005-doman-advantage-D-preregistered.md)完成训练及新开发对照，结果见第11节；其余后续阶段尚未启动。仍只处理决策改进。

### 10.1 先做候选D：直接学习动作优劣

A/B/C均在固定主体特征上回归已执行动作的收益。C虽改善价值预测，但新开发对照未胜过原始基线。因此下一轮建议保持同一数据、交叉拟合标签、主体和训练预算，单独比较训练目标：把逐手收益作为动作学习权重，直接优化合法动作的选择概率，检验优势加权动作学习能否改善决策。其假设是改变动作学习方式有益，不是假定标签已能可靠比较所有未选动作。

训练前只依据训练数据固定权重温度、裁剪范围和对原始策略的约束，不根据新开发牌局调参数；从原始基线初始化，只产出一个最终候选。保存原始模型作为对照，并与C在相同新种子上比较。固定100个开发种子组，D和C分别配对原始基线，共1600物理对局；具体种子和预算在实施前检查占用并预登记。本轮C的失败结果不进入下一轮调参循环。

刚完成的只读诊断在原始评分头、相同32个训练批次上得到：B标签标准差0.5705，C为0.2418；C收益回归的动作分支平均梯度范数0.4365，乘0.1后的CQL为0.0341，约7.8%。两项平均梯度方向相反，但CQL明显较小。该检查只覆盖训练初始位置，不能说明整个训练过程或因果；暂不支持把主要问题直接归因于CQL过强，也不据此盲目降低约束。

收益加权仍依赖旧策略实际探索过的动作，不能凭损失下降或动作变化率判断成功。继续条件须同时覆盖前二率、平均名次和四位率；未达到门槛即结束该候选，不扫描更多温度和检查点。

### 10.2 依据动作反馈补充探索数据（D结果后修正）

同时保留原始基线对照与不同对手的分项结果，避免只适应一个对手。旧轨迹作为保留原有能力的参考；新旧比例在训练前固定。全程离线模拟，不要求用户排队或人工凑训练集。

### 10.3 表示不足有证据时，才改变模型输入或解冻末段

若动作目标与数据覆盖经过比较仍不足，先分析留出局面中误差是否稳定集中于比赛长度或分数目标。只有有这种证据，才单独比较“显式东风剩余局数条件”和“有限解冻主体末段”。条件特征必须进入训练，不能复用已失败的仅推理时改进度编码；也不伪造场风。

上述两种变更分开比较，仍冻结其余主体和归一化统计，不能一次同时更换目标、数据和网络，导致无法判断收益来源。不默认全量解冻。
