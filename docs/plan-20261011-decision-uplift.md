## 2. 诊断：为什么九轮都没有结论

1. **开发门槛和样本量不匹配。** 100 组的平均名次差 95% 区间半宽约 ±0.07（组间差标准差约 0.37）。开发阶段同时要求“改善 ≥ 0.03 且区间上界 < 0”，实际要求真实效应 ≳ 0.075，这对在强基线上微调来说几乎不可能，所以门槛会系统性地否决所有候选。T（-0.025）这类真实但较小的效应会被误判为失败。
2. **算力远未用足。** 本机 RTX 5060 Ti 每小时约 4,800 场东风；评分层训练只需几秒。每轮只用了 0.5–1.2 GPU 小时，而 10-05 计划给的上限是 24 GPU 小时。1,200 组（约 9,600 场）配对评测大约 2 小时。
3. **训练数据太少，更新范围太窄。** 14–29 万条决策、主干冻结、离线回放，学习上限很低。Mortal 原始训练数据比这多几个数量级，靠评分层几乎不可能超过它。
4. **评测对手和实战对手不一致。** 开发对手是 3 个 v4 克隆，形成对称的强对手池，只能衡量“打赢自己”。实战对手是 FF14 玩家，牌风更松（立直、鸣牌、放铳率不同）。针对弱对手的收益在当前评测里完全看不到，而这恰恰是上分的主要来源。

## 3. 路线（按优先级）

### P0 仓库整理（0.5 天，必须先做）

- 提交 10-05 至 10-06 的实验代码、配置和报告，以及 `compare_models.py` 的改动。
- 处理仓库所有权：`git config --global --add safe.directory E:/SapphireServer/FFXIV-AutoMahjongSolver`。
- 用一场实机复核 3682892 的收尾修复，之后执行链冻结。

### P1 修正评测尺子（1–2 天，后续一切的前提）

1. **功效分析与新门槛。** 用已有的 9 轮逐组结果估计组间差方差，固定：
   - 开发筛选：500 组（约 1 小时）。只要求平均名次点估计 ≤ -0.02，且四位率差上界 ≤ +2pp，即可进入验收。
   - 正式验收：1,500 组（约 3 小时），沿用原有替换门槛（改善 ≥ 0.03、上界 < 0、四位率上界 ≤ +1pp）。
   - 严格性放在验收阶段，开发阶段只负责不漏掉有希望的候选。
2. **方差缩减。** 增加逐手点数差（同牌山配对）作为领先指标，并以配牌向听数、宝牌数作为控制变量做回归调整（CUPED）。先在已有 A/B/C/D/T 数据上回测，看能把区间缩小多少。
3. **FF14 拟真对手池。** 从 87+ 场实机归档中统计对手的立直率、鸣牌率、放铳率、和了打点和平均舍牌速度，用以下方式构造 2–3 种对手，并按统计量校准：
   - Mortal 加温度或 ε 噪声；
   - 更弱的旧检查点；
   - Akochan。
   每个候选同时报告“对 v4 克隆”和“对拟真池”两组成绩，后者作为业务主指标。
4. **重新判 T。** 在新尺子下，用 500 组新种子重跑一次 T vs 基线。这是唯一事先说明的复测，不扫描参数。

### P2 主线：放大规模的自对弈训练（约 1 周，24 GPU 小时内）

前提：P1 完成。各个变量逐个改变，每一步都过开发门槛才进入下一步。

1. **数据扩量。** 使用拟真对手池加 v4，生成 2–5 万场东风（约 4–10 小时），全部带完整轨迹；按 Doman 东风终局效用（初始取 B 的 `[1, 1, 0, -0.25]` 与 A 的 `[3, 1, -1, -3]` 两种）重训 GRP。
2. **解冻更多层。** 以 T 为起点，解冻全部残差块（BatchNorm 仍冻结或改为小动量），用 Mortal 原生 `train.py` 的 CQL 路线，并保留对 v4 的 KL 约束，防止能力退化。
3. **一轮在线策略迭代。** 用候选本身加入对手池再采一批，再训练一轮，然后冻结。只做一轮，避免无止境迭代。
4. 每个检查点只在 P1 的 500 组开发集上比较；胜出者进入 1,500 组验收。

### P3 低成本辅助（与 P2 并行）

- **298k 再评。** 它在半庄上点估计 -0.0625，东风上无差异。在拟真对手池上补测 500 组，成本约 1 小时。
- **Doman 规则差异核对。** 列出 Mortal 输入/奖励与 Doman 规则不一致的地方（役满上限、同分顺位、终局条件、食断），只修正会影响动作选择的项。

### 暂不做

- 4 局面隐牌后验和分叉续打标签：成本高，九轮中未产出可用信号。
- 继续只改收益或损失、但仍冻结主干的小数据微调（即 E 类方案）。
- 用少量实机对局判断胜率：50 场的名次区间约 ±0.3，只能做兼容性确认。

## 5. 执行结果（2026-10-12）

两轮全网络微调（[finetune_full.py](../tools/evaluation/finetune_full.py)，BatchNorm 冻结，CQL 1.0，各 16000 步）。平均名次差为候选减 v4 基线，负数更好。

| 候选 | 数据 | 对 v4 | 对噪声池（ε0.3 / 温度 1.0） |
|---|---|---|---|
| r1 第 8000 步 | 1 万场，我方 v4 | -0.003 [-0.031, +0.025]（500 组） | -0.055 [-0.130, +0.019]（300 组） |
| r1 第 16000 步 | 同上 | 0.000 [-0.028, +0.028]（500 组） | -0.088 [-0.165, -0.012]（300 组）；新种子复测 -0.025 [-0.080, +0.030]（600 组） |
| r2 第 16000 步 | 再加 1 万场，我方为 r1 第 16000 步，一半牌局对噪声对手 | -0.0085 [-0.038, +0.021]（500 组） | **+0.010 [-0.035, +0.056]（900 组）** |

r1 对噪声池的首个显著结果没有在新种子上复现。r2 在 900 组新种子上回到零附近。对噪声池合计 1800 组的加权平均约为 -0.02，与零无法区分。

结论：在单卡、约 2 万场离线数据的规模下，全网络微调与 v4 持平，没有可验证的提升，线上模型不替换。

噪声对手无法复现实战的放铳率（12.8% 对实战 15.2%），所以这项也没有直接衡量对真人的收益。
