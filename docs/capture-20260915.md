# 国际服 2026.09.15.0000.0000：两场实机采集

用户提供的版本为国际服 `2026.09.15.0000.0000`。截至准备时，本机只有 2026-07-31 的 Packet Logger 导出和 2026-08-02 的麻将归档；没有当前版本的网络证据。旧记录包含 363 条麻将报文、4 次起手，但不能验证新版本 opcode。当前配置模板仍为未验证，插件不会安装接收 Hook 或启用 Mortal 网络推理。

## 匹配前

1. 在 Dalamud 中重载本次构建的插件；构建包为 `Mahjong.Plugin.Dalamud/bin/Release/Mahjong.Plugin.Dalamud/latest.zip`。源码构建完成不等于正在运行的插件已经更新。
2. 插件设置保留游戏日志开启；先用 Hints（提示）模式，增强策略关闭，Mortal 关闭。当前本地配置原本为 Auto-play，请在游戏里明确切换。不要为了录包把协议模板的 `verified` 改为 true。
3. 使用之前生成 `packet-logs/Session ... .log` 的 Network Packet Analysis Tool / Packet Logger，建立新会话并开始录制。记录工具版本及其 opcode 名称表版本；名称表过期时原始包仍有用，但 `DOWN_ID` 标签不能直接作为证据。
4. 不按 7 月的六个数字 opcode 过滤。尽量保留这段桌局完整的接收包与原始载荷、opcode、长度、时间；不要只导出界面文本摘要。若工具名称可靠，可另存麻将消息筛选视图，完整原文件留在本机。

## 两场怎么打

- 开始匹配前启动记录，完整打完并离桌后再结束记录；每场单独导出一个 Session `.log`。进入桌局后确认记录条数持续增长，避免空录。
- 第一场提示模式，手动打，核对自己手牌、红五、场风/自风与分数；第二场在第一场没有读牌错误的前提下测试 Auto-play，也可继续手动采集。
- 遇到立直、暗杠/明杠/加杠、杠后宝牌、连续碰或多种吃牌选择时，记下大致时间，方便对齐原始包。正常打即可，不必为了覆盖事件强行鸣牌。
- 如果卡住，记下时间、当时弹窗和期望动作；不要马上删除/覆盖记录。截图可帮助确认未知红牌身份和本场供托。

## 打完以后

先离桌，让插件生成 `match-archives/<session>/summary.json`。新的摘要包含 `environment.game_version`、客户端变体、协议是否验证、降级原因和插件构建 ID。网络未验证时没有 `packets.ndjson` 是预期行为，此时使用单独导出的 Packet Logger `.log`。

导出后将两份 `.log` 放在原 `packet-logs` 目录，或者告诉助手实际文件路径；插件归档保持原位即可。导出文件必须真正保存，分析工具内的内存会话不会自动变成磁盘文件。

助手使用以下命令先审计，输出文件必须是新路径：

```powershell
node tools/audit-mahjong-capture.mjs "C:\path\to\Session.log" 2026.09.15.0000.0000 artifacts/network-audit-match1.json
```

报告仅含包头清单、动作码、证据哈希和未确认项，不输出原始载荷或名单消息 642。即使结构检查无错误，`verified` 仍为 false；必须把当前版本、UI 观察、红牌、本场供托、杠/宝牌和自杠回执与连续回放对应起来，才能启用实时协议。
