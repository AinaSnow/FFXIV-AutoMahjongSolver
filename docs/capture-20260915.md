# 国际服 2026.09.15.0000.0000：历史实机采集安排

> **2026-09-24 更新：原两场采集安排已完成，不再要求重复随机匹配。** 已有样本先按 [离线 Mortal 回放](offline-mortal-replay.md) 反复验证；确需补采时，必须给出具体缺失字段及已准备好的采集办法。下文保留为当时的操作记录。

用户提供的版本为国际服 `2026.09.15.0000.0000`。截至准备时，本机只有 2026-07-31 的 Packet Logger 导出和 2026-08-02 的麻将归档；没有当前版本的网络证据。旧记录包含 363 条麻将报文、4 次起手，但不能验证新版本 opcode。当前配置模板仍为未验证，插件不会启用正式协议接收或 Mortal 网络推理；可手动开启独立的原始调试录包。

## 匹配前

1. 在 Dalamud 中重载本次构建的插件；构建包为 `Mahjong.Plugin.Dalamud/bin/Release/Mahjong.Plugin.Dalamud/latest.zip`。源码构建完成不等于正在运行的插件已经更新。
2. 插件设置保留游戏日志开启；先用 Hints（提示）模式，增强策略关闭，Mortal 关闭。当前本地配置原本为 Auto-play，请在游戏里明确切换。不要为了录包把协议模板的 `verified` 改为 true。
3. 在设置 **Debug packet logger** 中打开 **Automatically record packets at mahjong tables**。显示 Armed 表示准备好，入桌自动建文件，离桌自动结束。不需要另开 Packet Logger；不要按 7 月的 opcode 过滤。
4. 详见 [内置自动录包说明](auto-packet-logger.md)。首次实机需确认 Saved 增长、Read rejects 不持续增长；仅显示 Recording 不足以证明捕获成功。

## 两场怎么打

- 开始匹配前打开自动录包，完整打完并离桌，每次入桌各生成一个 `capture-*.ndjson`。进入桌局后确认 Saved 持续增长，避免空录。
- 第一场提示模式，手动打，核对自己手牌、红五、场风/自风与分数；第二场在第一场没有读牌错误的前提下测试 Auto-play，也可继续手动采集。
- 遇到立直、暗杠/明杠/加杠、杠后宝牌、连续碰或多种吃牌选择时，记下大致时间，方便对齐原始包。正常打即可，不必为了覆盖事件强行鸣牌。
- 如果卡住，记下时间、当时弹窗和期望动作；不要马上删除/覆盖记录。截图可帮助确认未知红牌身份和本场供托。

## 打完以后

先离桌，让插件生成 `match-archives/<session>/summary.json`。新的摘要包含 `environment.game_version`、客户端变体、协议是否验证、降级原因和插件构建 ID。网络未验证时正式归档没有 `packets.ndjson` 是预期行为；原始调试包在独立的 `debug-packets/` 目录。

点击 **Copy packet log folder** 获取路径，告诉助手这个目录即可，不必手动导出。保留对局归档和调试原文件；收集完后关闭调试开关。

助手使用以下命令审计（输出路径必须不存在）：

```powershell
node tools/audit-debug-packets.mjs "C:\path\to\capture.ndjson" 2026.09.15.0000.0000 artifacts/debug-audit-match1.json
```

报告仅输出 opcode、长度清单和完整性信息，不输出原始载荷。`verified` 始终为 false；必须把当前版本、UI 观察、红牌、本场供托、杠/宝牌和自杠回执与连续回放对应起来，才能启用实时协议。原始文件可能包含玩家信息，不要公开上传。

若使用外部 Packet Logger，保留未按旧 opcode 过滤的完整 Session `.log`，记录工具和名称表版本，并继续使用 `audit-mahjong-capture.mjs` 审计；不需要为本次内置采集同时运行它。
