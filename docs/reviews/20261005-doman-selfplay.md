# 2026-10-05 东风自对战数据入口验收

## 交付与结论

已接通东风自对战、规则一致的训练牌谱读取器、四玩家可见输入导出及独立数据验收。能够本地生成后续训练素材，无需用户为了凑随机局面反复排队。尚未训练新权重、校准 GRP 或证明棋力改善；线上插件、模型和配置未修改。

训练组 epsilon=0.02、温度 0.05；开发组强制 epsilon=0。AMP 关闭、cuDNN deterministic，模型进度编码仍为 native。东风训练样本包含 2 次暗杠、3 次加杠、5 次新增宝牌；这些是模拟事件，不代表 FF14 网络对应路径已通过验证。

## 修复与验证

- 原版 GameplayLoader 默认按标准半庄构造 PlayerState。新 dataset adapter 把比赛长度同时用于 arena 和读取器，避免第五杠等合法动作掩码失配；保留原始场风与编码。
- 隔离引擎原生测试 39/39，通过新增规则传播与对手起手牌不可见回归。rules revision 仍为 1，dataset revision 为 1。老 v1 库仍支持历史评测，但不能用于新东风导出。
- Python 测试 74/74，无跳过；覆盖文件篡改、额外样本、重复种子/轨迹、未知规则/分组标记、非法动作、NaN、错误手局关联、数据失败状态和原生 bytes 局号转换。
- 东风 train、东风 development、标准半庄 development 三个目录通过联合 verify_self_play 审计：完整四视角、哈希、去重、名次/得分重建与掩码校验均通过，无跨集合重复种子或轨迹。
- 首次导出发现 PyO3 的 u8 局号数组返回 bytes，已修复并加入回归。该目录保留 failed 标记，不能作为可用数据；成功重跑使用 r2 新目录。最初一次构建的换行问题也保留 failed 清单，后续构建独立通过，未覆盖失败记录。
- CI 增加 Python 3.13 / NumPy 2.5.3 校验依赖，避免数组测试因缺 NumPy 跳过。本轮未推送，未声称远端 CI 已通过。

本轮未修改 C# 插件，不重复构建或热重载。数据检查不等于对上游全部麻将规则进行形式化验证；保留完整 FF14 规则差异说明。

## 后续工作

1. 先登记下一批训练种子、开发种子、固定样本量及对手混合方案，再扩量。验收工具联合核对既有目录，避免把重复生成当数据扩充。
2. 建立东风 GRP/名次奖励校准与隔离训练配置。目标仍为平均名次，兼顾四位率；不能把训练损失降低或模仿旧模型当棋力提高。
3. 小规模微调候选先过开发集对照，冻结后再做独立最终验收。现有 checkpoint 缺原优化器与 GRP 状态，只能初始化微调，不能恢复原训练进度。
4. 多赢家本场/供托、包牌、立直后杠和实际游戏时限等规则差异仍待验证。当前数据按实验规则标记，不声称完全等同 FF14，也不换算 Rating。

用户无需额外提供抓包或持续对局；下次正常游玩仍只需观察前一批自动离场修复的效果。
