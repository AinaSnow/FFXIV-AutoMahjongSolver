# 2026-09-25 和牌提示残留修复与策略收益边界

## 问题与改动

上一轮八场复核定位到三个 `Ron → Pon/Chi` 转换：荣和标签只出现约 12–16 ms，但自动操作继续保留它，使 Mortal 的正常回复被拒绝，跳过位置从 1 错算成 2。三个场景合计出现六次模型超时，以及三次跳过无效。

本次修复：

- 荣和必须来自当前 UI，消失的 Ron 不再合并到吃、碰或跳过窗口。真实荣和仍优先处理，已经派发的和牌仍可进行第二次确认。
- 保留原有自摸到 state-6 出牌列表的特殊过渡。该过渡仅允许接受已选定的自摸；不会给普通跳过增加虚构选项。
- 点击吃碰、和牌、立直确认或跳过前，再读取当前选项，重新计算按钮位置。手局、手牌、红牌身份、牌山或牌河/副露已改变时取消旧操作；新出现和牌提示时不派发旧 Pass。
- 原始 UI 快照先补齐手局信息，再与已发布局面比较，避免把缺少手局编号的 UI 读取误当成另一局。
- 提示模式也可能先看到短暂错误标签。与和牌提示冲突的模型回复暂存在单个槽位，只在同一手牌/事件下重试；任何新网络事件、进程停止或手局隔离都会清除。队列中的真实 hora 仍可越过冲突回复被处理。
- 二次确认增加手局编号和公开弃牌/副露核对，避免玩家吃碰后牌山未变化时沿用旧确认。

不调整原有超时默认值，不更换 Mortal 权重，也不扩大未验证的网络协议范围。

## 胜率方面的结论

沿用上次相同八场、37 小局，不把本次修复后的预期效果混入旧数据。Mortal 501/581 次决策（86.2%）；平均名次 2.625。它们不是相同种子下的配对试验，不能据此认定胜率改善或退步。

进一步核对发现：

- 有和牌派发的 8 个小局共 16 次点击，包含初次声明与后续确认；全部记录到状态变化，没有这些点击的超时记录。状态变化不是逐条服务端确认。
- 按连续状态日志筛选持续至少 700 ms 且已有结束状态的和牌窗口，11 个窗口都有对应和牌动作；动作时间容许窗口结束后 250 ms，以容纳同步回调先记录新状态的顺序。该检查不能证明所有短暂提示都是真实和牌，也不能证明全程绝无漏和。
- 37 个小局文件中有 36 个 `hand-end`：17 个 tsumo、12 个 ron、1 个 draw、6 个 unknown；这些仍是推断标签，另一个文件没有 hand-end。不能把未知或缺失结果强行计为输牌，不能直接给出可信的和牌率/放铳率或用其训练奖励。

当前最直接的改进是让现有模型的动作可靠执行。本次消除的是已复现的回复丢失、按钮错位与重复等待，不能换算成承诺的胜率增幅。

后续顺序：先用现有归档验证导致隔离的 `0x140`、`0x400` 和 `0x113` 事件及后续补牌/宝牌，减少整局退回本地策略；再完善结算与动作结果标签，做离线固定种子对照。现有 libriichi 标准半庄结果不能直接当作 FF14 东风战提升证明，FF14 规则适配完成前不晋升默认策略。当前不需要为已定位的三个故障追加随机对局，也不据八场成绩改动模型权重。
