## 交付行为

- 对手暗杠、明杠、加杠及已观察到的连续加杠产生真实 MJAI 事件；只有对应玩家的补牌包才产生 `dora → tsumo`，每次一次。

- Mortal 可在对手加杠后响应 UI 明确提供的抢杠和牌；下一补牌事件关闭此窗口。其他玩家的延迟和牌响应不能用于此窗口。

## 独立宝牌核对

新增 `tools/audit_kan_dora.py`，在游戏结束后比较三个独立来源：开局/补牌的指示牌、已公开的赢家手牌和副露、结算的宝牌条目。这个工具与生产解码器及 Mortal 回放分开，不把末局公开手牌用于先前推理。

结果包 639/640 的首个赢家块中，uint32 偏移 0 是和牌张，4 是未含和牌张的闭手牌数量，16 为赢家席位，52 起为闭手牌；牌种取低字节，红五保留 `0x100`。役 ID 数组在 104，数值数组在 168，各 16 个；ID 23 的数值低三字节分别是总宝牌、里宝牌、赤宝牌。232 起最多五个里宝牌指示牌取低字节，`0xff` 为空；高位标记不是新牌种。第二赢家块、其他结算字段和无公开手牌的边界不作解码声明。

- 131 个可核对的首赢家结果全部一致；另 1 个无公开和牌手牌的结果明确跳过。
- 11 个含杠结果一致；其中 4 个新增宝牌确实贡献分数，能排除“忽略新增宝牌也碰巧一致”。其余零收益结果只提供一致性检查，不单独证明指示牌取值。
- 保留重复指示牌：多个同牌种指示牌可同时存在，不能按牌种去重。
- 匿名构造测试包含错误指示牌必须导致不匹配、四张杠牌的宝牌计数、赤牌、带标志的里指示牌、风/三元循环和无公开手牌跳过。
