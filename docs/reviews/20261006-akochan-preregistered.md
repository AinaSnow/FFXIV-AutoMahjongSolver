# Akochan 东风决策对照预登记（2026-10-06）

用户要求尝试 Akochan。仅比较决策，不处理执行、UI、协议工程 bug，不替换线上模型。

## 固定候选与比较范围

- 官方仓库 https://github.com/critter-mj/akochan ，固定提交 `53188a0b926fbab38177f88c3cd87d554cf412af`。保留原始决策源码、参数和 `setup_mjai.json`（排名效用 `[90,30,-30,-90]`），不扫描策略参数。
- 使用其原生东风启动字段 `kyoku_first=4`，场风仍为真实东场，保留赤宝牌。其终局价值模型仍含三万点和延长战假设，本轮不改动。比较结论仅适用于这个现成配置，不代表定制后的 Akochan 上限。
- 复用现有 Doman v2 规则模拟、Mortal 固定原始权重、三个原始 Mortal 对手、种子 key=42 和候选四座轮换。双方实际遵守同一 Doman 模拟规则。
- 隔离复制原生引擎，最小适配只将 Akochan 启动从半庄改为东风，并在送入进程前屏蔽他家起手牌和摸牌；不发送种子、未来牌山或观测元数据。自己手牌、公开动作与真实分数保留。动作由同一模拟器检查合法性，非法动作直接中止，不以原模型替打。
- Akochan 编译 NPROCS=2、OpenMP 两线程；Mortal GPU FP32、两 CPU 线程、关闭探索/AMP、确定性 cuDNN。每批一个种子组，固定计算路径。依赖只解包至实验目录。

## 预检与按速度选择规模

1. 原生适配的可见信息测试和相关 arena 测试必须通过。
2. 预检种子 `1012000`：候选 4 场，基线 4 场。另用原有未改库重跑相同基线 4 场，要求动作 hash、最终点数、名次完全一致。12 场总计，不计入正式开发统计。每次预检运行上限 20 分钟；入口构建/兼容失败可修复必要适配后重跑，失败记录保留。
3. 正式种子从 `1013000` 起连续，组数仅按成功预检时间 t 秒确定：`N=min(100,floor(3600/(1.5*t)))`，t 包含候选和基线共 8 场评测耗时。N<8 则本轮止于可行性结果，不为凑样本延长。候选成绩不参与规模选择。
4. 确定 N 后先保存配置，再执行 N 个配对组、8N 个物理对局。正式运行硬上限 90 分钟，不按中途成绩提前停止，也不在观察结果后增量。若超时或非法动作则保留所有输出、报告未完成，不把已完成片段宣传为完整预登记结果。

## 指标与判定

平均名次为主，前二率和四位率分别报告，并提供和牌率、放铳率、点数与候选决策耗时。以种子组（同组四座相关）做固定随机数 90731、10000 次配对 bootstrap，报告 95% 区间。

仅当平均名次差<=-0.03、其区间上界<0、前二率差区间下界>0，且四位率差区间上界<=+0.01，才将其列为值得独立验收的候选。本轮是开发筛选，无论结果如何均不直接替换线上模型，不将模拟前二率换算成真实玩家胜率/FF14 Rating。

交付官方版本和二进制/参数 hash、隔离构建/适配、逐场日志和配对结果、已知决策规则假设差异，以及是否值得继续的结论。已知 Doman 模拟限制沿用已有报告，不扩展为边界治理。

## 预检后的执行修订（正式开发数据产生前）

预检 8 场已实际完成：Akochan 四座 341.08 秒，Mortal 四座 19.87 秒，共约 360.98 秒。原公式只能给出 6 组，触发串行成本门槛。该门槛说明两线程串行采样成本高，不是棋力失败。预检结果已可见，明确排除于正式统计。

利用现有 16 逻辑核改用 4 个独立进程，每个仍以两线程、每批一组、相同决策配置运行；总并发计算资源改变，单局推理方式保持相同。正式规模公式修订为 `min(100,floor(3600*4/(1.5*t)))`，得到 **26 组 / 208 场**，全新种子 **1013000–1013025**，分为固定连续区间 7/7/6/6 组。保存配置后才启动，所有组均保留。实际并行速度不保证四倍，仍使用 90 分钟总墙钟硬上限，超时按未完成报告。

这是一项明确的资源与规模修订，不宣称原串行预登记已原样执行。其目的为在有限墙钟时间取得可比较样本；不依据预检名次决定候选、策略参数或正式种子。正式指标和继续门槛保持不变。

实现记录：旧源码编译缺少显式 cstdint，使用编译参数补入；官方 pipe 分支逐字提取为独立入口，避开本实验不用的旧 TCP 客户端 Boost API，AI 源码与参数未修改。Boost 只解包到实验目录，运行参数按 hash 核验后复制到 WSL 临时目录，避免跨盘小文件读取开销。初次 8 场运行在报告汇总时发生字段命名冲突；已保存完整逐场 JSONL 和日志，仅修正汇总字段后重建报告，不重跑/筛选牌局。另用原始未改引擎完成 4 场基线复核，正式启动脚本须断言其动作 hash、点数、名次与预检基线完全一致。
