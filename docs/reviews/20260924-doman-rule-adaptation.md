# 多玛规则适配实施（2026-09-24）

依据 [官方规则审查](20260924-official-rules-audit.md) 实施。此轮修复本地规则、操作合法性和评测边界，不更改 Mortal 权重，也不将候选网络协议标为已验证。

## 已落地

| 差异 | 处理 | 验证 |
|---|---|---|
| 单项/复合役满 | 多玛单项役满统一 13 番；复合上限四倍；Scorer 执行规则集上限 | 大四喜、纯正九莲、四重役满及通用规则对照 |

## 格式及兼容

- 快照 schema 7：新增 `InitialDealerSeat`、`Legal.DiscardRestrictionKnown`；新增字段缺失时分别是未知初始顺位、旧空集合语义。事件回放继续从原始事件构造当前 schema，不改写旧 golden。
- 游戏日志 schema 6：状态增加 `initial_dealer`、`discard_restriction_known`、`discardable_tiles`。旧日志及归档仍可读；旧同分归档没有初始顺位时继续未知。
- 用户的模式、Mortal 开关、自动操作配置及模型文件保持原值。增强策略继续默认关闭。

## 仍未完成的适配

1. 当前候选网络协议对杠、补牌和新增宝牌的连续事件，以及非零供托与立直确认时序，仍未全部验证。因此本轮不能宣称 Mortal 已恢复完整实战支持。
2. UI 局部状态跟踪依赖从宣告至首次舍牌的连续观察；中途加载、手动取消或漏掉副露时，不把旧副露当作刚发生的吃碰，也不凭空声称已知逐牌限制。尚未接入 UI 每张牌的可点击标记。
3. 比赛模式的实时自动识别、计时截断、多赢家、流满及责任支付的完整结果事件仍未接入；当前档案不能据分差重建这些细节。
4. 已核对本机固定版本 libriichi 的 `arena/one_vs_three.rs` 与 `arena/game.rs`：公开接口固定标准半庄，可因未达 30000 分延长；末局庄家结束也要求 30000 分。仅将策略输入改成一轮并不能实现 FF14 快排。需要单独适配和验收对战引擎，现有正式评测不会冒充兼容。

## 检查及部署

全解决方案回归、Python 评测门禁和独立 MJAI 入口编译均纳入本轮检查。Release 构建直接更新原 dev 目录；实际游戏内效果需要热重载后复查，离线通过不代表已提高胜率。无需刻意制造稀有役种，正常打一把即可观察立直交接和禁打处理。
