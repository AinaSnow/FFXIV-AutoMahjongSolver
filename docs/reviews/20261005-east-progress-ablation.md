# 2026-10-05 东风进度特征离线实验

## 结论

没有证据支持上线这项特征变换。20 个新开发种子组、160 场配对实验中，平均名次差为 0，前二率同为 50%；候选四位率高 3.75 个百分点。小样本不能确认变好或变差，但没有理由替换当前实战设置。线上权重、配置、runner 和原生库均未修改。

| 平均名次 | 2.500 | 2.500 |
| 一／二／三／四位次数 | 23 / 17 / 17 / 23 | 20 / 20 / 20 / 20 |

| 每手放铳率 | 13.94% | 14.71% |
| 平均牌桌得失分 | -776.25 | 0.00 |

按种子组 bootstrap 的平均名次差 95% 区间为 [-0.1375, +0.1500]；四位率差区间为 [-2.50, +10.00] 个百分点。每组四座有关联，不把 80 个座位结果当 80 个独立种子。

基线与三家对手使用相同确定性策略，轮换四座后的 2.5 / 50% 是这个对称对手池的性质，不能解释成在 FF14 只能一半上分，也不是用户池胜率预测。

## 变更边界

仅候选的 v4 观测第 27 行从东一到东四的 0、1/7、2/7、3/7 变为 4/7、5/7、6/7、1。保持真实东场和自风、局号、得分、手牌、其他观测行与合法动作不变。没有伪造南场，也没有更改役种或计分。其他由原生状态派生的特征不随这一个通道改变；这不是完整的东风专用观测或训练。

适配前检查架构、矩阵形状、东场、局号与原始进度，防止未知布局和重复适配。禁止隐藏观测。只有 doman-quick 且候选/基线权重相同时可启用；默认 native。模型报告同时记录权重和特征变换，避免把同权重、不同输入误标为同策略控制组。

## 实验身份与复现

- 引擎：隔离 Doman v1，Mortal 基础提交 0cff2b52982be5b1163aa9a62fb01f03ce91e0d2。
- 权重：现有 model_v4_20240308_best_min.pth；候选、基线、三家对手相同。
- 开发种子：1003000–1003019，key=42；20 组一个 GPU 批次；每角色轮换四座。
- CUDA，2 CPU 线程，AMP 关闭，cuDNN deterministic，随机潜变量和 epsilon 关闭。
- 运行耗时约 132 秒（不含启动加载）；6007 次候选观测应用变换。

- 原生布局检查覆盖 32 案例，仅第 27 行改变；Python 单元测试 65/65 通过。

## 控制组验收

另跑同一组 20 个种子、相同批大小的 native 对 native，共 160 场，输出到 artifacts/evaluation/east-progress-control20-20261005。所有 80 个配对座位的游戏事件哈希、名次、得分、手数、和牌和放铳数完全相同，control_passed=true，名次/四位差及区间均为 0。

额外逐项核对实验基线与控制组基线：80 份结果和游戏事件哈希完全一致。本轮共运行 320 场，但仍只有 20 组实验种子；控制组不是额外的策略改善样本。原生布局与完整牌谱校验通过，不等于 FF14 规则全量一致或实机退出验证通过。

控制命令沿用实验参数，移除 --candidate-observation east-progress-v1，并把 --output 改为上述 control20 目录。

## 后续安排

1. 当前实战保持原权重、原进度编码。离场稳定性修复独立构建，正常游玩时验证即可，不要求追加随机采样。
2. 本实验保留为可复现的开发工具。不因更低放铳率或一位次数增加就上线；其前二率与名次未改善，四位率区间也远未达到安全门槛。
3. 下一步训练路线先让 self_play 接入隔离东风引擎，记录比赛长度、可见输入与终局名次，并补齐规则验证；再讨论小规模微调。无需靠用户连续排队凑训练集，也不能把当前实机档案全部视为训练就绪。
4. 若重新评估进度特征，先登记未使用的开发种子和固定样本量，再运行；不反复查看显著性后临时停止。冻结候选后才使用独立验收种子（默认 1000 组 / 8000 场）与既定门槛。

规则仍未完整对齐 FF14：多赢家本场/供托、包牌、立直后杠边界和游戏计时等保留限制；不换算 Rating，不声称本轮提高胜率。
