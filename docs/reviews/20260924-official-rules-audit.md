# FF14 官方规则与当前实现差距（2026-09-24）

本次为规则和源码审查，基于本地提交 3fb94ab；不把官方规则文字当成网络字段偏移的证据。运行中的候选协议仍未验证。

## 修正此前采集要求

5.4 增加了快速比赛，与完整比赛分开；其基准长度分别是四局和八局，实际局数还受连庄影响。[官方 5.4 更新说明](https://na.finalfantasyxiv.com/lodestone/topics/detail/230f6e0af3536f9a40654d783c8c2f1094131070)

据此，结合现有完整样本从东一到东四结束且无人负分的记录，当前采集符合快速对局。不能要求这些样本必须出现南场。此前报告中的“缺比赛长度/场风变化”应分成两个事项：运行时仍需可靠识别具体模式；南场回放属于完整比赛支持的验收范围，不是快速模式的必备样本。也不能凭五份日志反推比赛固定五局。

官方还说明立直后会自动打出新摸入的非和牌牌；里宝牌直到和牌后才揭示。因此立直成功后应把控制权交还游戏的自动摸切，继续处理和牌及合法暗杠提示；决策时不能读取或猜成已知的里宝牌。[官方基本规则](https://na.finalfantasyxiv.com/lodestone/playguide/contentsguide/goldsaucer/doman-mahjong/)

最近两场服务端摸切与这一行为相符。`unconfirmed-state-change` 仍是准确的归因标记：它不能证明点击生效，也不应直接计为出牌失败。后续自动操作调整要以宣告确认后的本局状态为依据，不能在第一次宣告舍牌前停止操作。

## 已确认的实现差距

| 优先级 | 项目 | 源码现状及影响 | 所需验证 |
|---|---|---|---|
| 高 | 杠、补牌和新增宝牌 | `MahjongPacketMjaiDecoder` 对所见杠类事件明确抛错。`MjaiDora`、归约器与三种杠的数据结构已存在，但网络入口没有完整供给，不能把“有类型”视作接入完成 | 继续已有 0x400/0x130/0x140、0x200、0x210/0x212 连续样本分析，交叉确认宝牌、顺序及自身回执 |
| 高 | 供托与确认时序 | 起手仍填 `Kyotaku: 0`；立直弃牌直接合成 `reach_accepted`。`PublicStateTracker` 传 `knownCounters:false`，已解析的本场也还没有单独作为已知字段并入正式局面 | 非零供托及宣告是否被和牌打断的事件样本；按字段分别维护已知性，不能用常数冒充观测 |
| 高 | 吃碰后的禁打牌 | `BaseEmjVariant.BuildLegalActions` 给出空 `DiscardableTiles`；`DiscardScorer` 把空集合当不限制。`LiveMortalBridge.TryMapDecision` 对弃牌只检查回合标记和手里有这张牌，不检查逐牌禁打。可能反复推荐或尝试游戏禁止的舍牌 | 接入 UI 可点击状态或由完整事件计算禁打集合，并在派发前复核；增强鸣牌搜索也应使用鸣牌后的限制 |
| 高 | 已立直状态与后续操作 | `ActionStateMachine` 能记住宣告并清除第一次舍牌目标，但 UI 快照仍未提供确认后的 `OurRiichi`。策略会继续生成立直建议，自动操作仍会尝试后续 slot 13 点击 | 同步本局已确认立直；首次宣告舍牌、自动摸切、和牌、暗杠分开处理。无需强求自动摸切触发插件回调 |
| 中 | 规则集并非独立多玛规则 | `DomanRuleSet.YakuRules` 直接引用通用 Riichi 列表。`DaisuushiiRule` 使用双倍役满，`ChuurenPoutouRule` 对纯正形态也翻倍 | 给多玛单独的役满规则配置和计分用例，保留通用日麻规则集的原有语义 |
| 中 | 役满上限配置未落实 | `DomanRuleSet.MaxYakuman=2`，测试也断言为 2；但 `Scorer` / `StandardScoringRule` 根本未消费这个属性。因此问题既是参数不符，也是没有执行上限，不能说当前实际必然最多算两倍 | 配置与计分路径一起修正，分别测试单项与复合役满 |
| 中 | 同分顺位与终局 | `PlacementAdjuster.RankOf` 对同分者给相同名次；归档同分时返回未知。快照不保存初始顺位。`IsLastHand` 只看已知比赛长度、场风及第四局，未表达时间截断和最终庄家结束条件 | 保存初始座次、比赛模式及结束原因；不要用相对自身 0 作为同分优先级 |
| 中 | 流局、多人和牌和责任支付 | 日志仍按分差形状推断单一荣和/自摸。流局听牌罚符也可能是一正三负；只靠符号不能区分。局末网络包现在仅输出 end_kyoku。模型和本地日志缺完整结果语义 | 结果事件应包括原因、赢家集合、实际分数变动；离线环境单独比较相应结算，不必等真人凑出每一种役 |
| 中 | 振听信息用于策略 | `FuritenDetector` 仅供旧模拟器使用；实时快照没有临时/立直后振听字段。本地评分能估牌型价值，但不能据此认定当前可荣和 | 执行动作以实际合法提示为准；对默听/立直收益的估计纳入可和方式，避免高估荣和机会 |
| 低，仅特定模式 | 禁食断好友桌 | `AllowsKuitan` 固定 true，`TanyaoRule` 也未依据该设置排除副露断幺。匹配排位本身允许食断，不能把这项当普通排位的未验证规则 | 先显式声明支持模式；若支持禁食断好友桌，再增加模式配置及专用测试 |
| 评测 | 快速对局与半庄混用 | `tools/evaluation/mjai_adapter.py` 固定 `scheduled_rounds=2`，当前对战环境是标准半庄 | 快排和完整比赛分别建基准。libriichi 的规则/模型适配必须列出差异，半庄报告不能直接作为 FF14 快排强度验收 |

禁打牌和振听的游戏约束、以及游戏会禁用对应操作，见[官方常见问题](https://na.finalfantasyxiv.com/lodestone/playguide/contentsguide/goldsaucer/doman-mahjong/faq/)。这支持接入真实合法动作，而不是绕过游戏的禁用状态。

官方役表把大四喜、九莲宝灯列为单项 13 番役满；与上述通用规则实现存在差异。[官方役表](https://na.finalfantasyxiv.com/lodestone/playguide/contentsguide/goldsaucer/doman-mahjong/yaku_list/)

官方详细规则确认复合役满上限四倍、同分按初始风位排序、无西入、负分结束，以及双响、途中流局、流满和责任支付等特殊结算。应把这些规则落实为明确配置及独立用例。[官方详细规则](https://na.finalfantasyxiv.com/lodestone/playguide/contentsguide/goldsaucer/doman-mahjong/special_rule/)

匹配排位允许食断，禁食断是另一种四人好友桌；官方还说明段位/评级依据名次及对手评级，结束持点数不直接参与评级。[官方比赛说明](https://na.finalfantasyxiv.com/lodestone/playguide/contentsguide/goldsaucer/doman-mahjong/play_mahjong/)

## 修复与验收顺序

1. 首轮明确限定已经采集的国际服快速排位模式；加入可靠模式识别。完整比赛和禁食断好友桌分开验收，不为本轮追加无关采集要求。
2. 补齐公开事件与逐牌合法性；同步已确认立直。任何缺口继续隔离当前手局，未知协议版本继续停用网络推理。
3. 本地规则差异可依据官方规则直接编写构造用例，修正多玛评分、同分顺位及结果分类，不要求用户在真实游戏中刻意制造稀有情况。
4. Mortal 恢复前先做“真实事件→模型输入→合法推荐”的回放和影子验证；罕见计分规则缺口与基本进程/协议可用性分别记录。官方文字不能替代实际报文和 UI 的字段对应证据。
5. 独立评测快排表现。优化目标继续以名次和避四为主，不能用多赚原始点数替代上分效果。

本次只记录规则审查及验收范围修正，没有改变运行行为、协议 verified 标记或策略默认值；无需为文档重新运行游戏。
