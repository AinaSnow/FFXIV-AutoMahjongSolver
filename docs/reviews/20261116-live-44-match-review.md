## 异常归因

计数很低，但四次 Mortal 超时全部发生在鸣牌窗口，且不是推理耗时问题（同场 Mortal 评估约 50 ms）。以下是日志与抓包能直接看到的事实。**2026-11-16 更新**：四次均已在 [A3 复核](20261116-a3-call-window-stalls.md) 中定位，下面各节末尾的“复核结论”替代了原先的假设。

### 1. 对手吃牌瞬间出现空候选的“碰/过”提示（2 次）

`match-20261115-091643Z` 第 1 手与 `match-20261115-151730Z` 第 4 手：

1. 对手舍牌，我方出现碰提示并已正常 Pass（`state-changed`）。
2. 约 3–6 秒后收到 `0x0211` 类型 `6` 的报文（载荷带两张相邻牌，推断为另一家吃牌），20 ms 内 UI 状态码变为 15，插件记录 `call-prompt`，`legal = "Pon, Pass"`，但 `pon`/`chi`/`kan` 候选均为空。
3. 此时没有任何新的对手舍牌包，`LiveMortalBridge` 停在 `waiting for authoritative opponent discard`，约 5.6–6.2 秒后超时走本地兜底 Pass；吃牌家的 `0xA10` 舍牌包在我方 Pass 之后 0.7–1.5 秒才到。

假设：这是上一张舍牌的碰提示在他家鸣牌时被 UI 重新置为状态 15 的残留提示，而不是新的鸣牌机会。待确认的是服务器当时是否在等待我方响应；如果是，则每次会让全桌多等约 6 秒。

复核结论：残留提示成立；**服务器没有等待我方**。331 次他家吃/碰/大明杠中有 36 次出现同样的残留行，其中 34 次我方没有任何点击，桌面照常推进，鸣牌到吃碰者舍牌的间隔与无残留行时相同（中位数约 1.6 s）。两次超时只是吃碰者本身慢，兜底 Pass 点击没有生效（`superseded`）。“候选为空”也不是区分特征：36 次中有 12 次带候选。

### 2. 自家碰后舍牌紧跟一个碰提示（1 次）

`match-20261115-111808Z` 第 1 手：我方碰后舍牌（`0xA10`，actor 0）20 ms 后出现 `Pon, Pass` 提示（候选 `pon: [1]`），此时最近一张网络舍牌是自己的，Mortal 无对应反应，约 6.8 秒后超时 Pass。是否与 [dispatch-protocol.md](../dispatch-protocol.md) 记录的“连续第二次碰停顿”为同一问题尚未核对。

复核结论：不是“连续第二次碰”。我方的碰和随后的舍牌都已由服务端确认，提示是自家舍牌后 UI 重新显示的残留行（与第 1 类同源），任何人都不能对自己的舍牌鸣牌。41 场有报文的归档中这类行共 118 次，只有这一次因为下家思考 10.9 s 而超时。

### 3. 立直后暗杠未执行（1 次）

`match-20261115-113816Z` 第 1 手：立直一发巡摸到第四张中，Mortal 给出 `AnKan`，动作经 `call:list-select(option=0)` 派发后结果为 `superseded`，提示仍停在 `AnKan, Pass`，其后没有重试；8 秒后超时，经 `opcode-8(riichi-kan-pass)` 放弃暗杠并摸切。这一次有实际损失（少一次岭上摸牌与杠宝牌）。立直后的暗杠选择路径与普通暗杠不同，需要单独核对派发路径。

复核结论：立直暗杠弹窗没有动作标签，`AnKan` 因此走了 `SelectItem`。这条路径在 state 6 无标签弹窗上从未生效过（2026-09-23 自摸、2026-09-24 立直杠 Pass 都是同样表现），本次也没有回调、没有 `0x130`。没有重试，是因为派发返回 `Ok` 后桥接进入“等待服务端杠回执”，推荐被清空，直到约 8 秒后超时兜底；同时 `MeldTracker` 记下了一个不存在的暗杠。派发路径已改为 `[11, 行号]`，是否生效仍待实机确认。44 场中没有任何一次成功的立直暗杠。

### 4. Pass 点击超时（3 次，均在 11-14）

`match-20261114-113224Z`（1 次）与 `match-20261114-120723Z`（2 次）：`call:opcode-11(option=1)` 的 Pass 在观察窗口内没有等到状态变化，记为 `failed_actions`。11-15 的 25 场没有复现。

复核结论：这两场当时没有加载可用的 7.58 协议（纯 UI 模式，决策全为 `stable`）。三次都是他家摸牌后残留的旧提示，`[11,1]` 对它无效。网络模式下同类提示由 `[8]` 过期提示取消处理（本批 149 次，无超时），所以 11-15 没有复现。
