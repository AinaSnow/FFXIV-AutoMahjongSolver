## 负分为何导致漏结算

原归档只统计 7 次结算，最后分数停留在第八小局起手的 `[200,35000,40400,24400]`。实际最后观测到的 UI 结算分数为 **`[-800,37000,39400,23400]`**，自身第四、相对初始分数 -25800。这不是原 summary.json 所写的 200 分。

证据来自 `memdumps-20260924-081350-193.ndjson`：

| UTC 时间 | UI 状态 | 观测 |
|---|---|---|
| 08:13:58.031 | 29 | 自动“下一步”，同步回调已捕获 |
| 08:13:58.363 | 35 | 手牌已清空，暂时仍为旧分数 |
| 08:14:03.043 | 无可用快照 | action 160 超时，state_after/hand_after 均为 null |
| 08:15:30.057 | 27 | 结束界面，手牌空，分数 `[-800,37000,39400,23400]` |

变体探测和快照读取原来都拒绝任何负分。结算更新后快照丢失，因此 GameLogger 看不到最终状态 27，离桌写成 hand-incomplete；操作监测也失去了可比较状态。原始 UI 已显示 29→35，故该超时不能解释为“下一步完全没生效”。修复后此路径已通过离线回归，仍需后续实机确认。

修改：

1. 变体探测与快照读取使用同一分数范围校验，允许配置上限内的正负分；超范围数据仍被拒绝。
2. 归档根据有效 hand-end 和四家观测分数记录结算，移除分差必须近似零和的假设。桌上立直押金保留或被领取时，分差总和可不为零；损坏字段依然使归档标记不完整。
3. 非零和分差不再仅按正负人数猜测自摸/荣和，记为 unknown，保留 result_inferred 标记。本场最后分差 `[-1000,+2000,-1000,-1000]` 原本会被误猜为自摸。

最后观测分数总和为 99000，与最后小局一根未回收到四家分数中的立直押金相符。没有凭推测把额外 1000 分加给某位玩家；比赛最终奖励结算仍需独立字段验证。原抓包、内存记录及原归档未改写。
