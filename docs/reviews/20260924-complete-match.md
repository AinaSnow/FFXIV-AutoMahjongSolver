## 本场复现并修复的问题

1. **牌山估算归零后变回 70，误开新局。** 13:26:24 左右，各家弃牌数从总计 70 增至 71；旧公式遇到负数返回初始 70，于是旧手牌被当作重新配牌，首局被拆成两份。现在把估算限制在 0–70，并要求旧牌河已清空才能以牌山跳升判断新局。牌山仍是 UI 估算，不能当作已核实的精确余牌数。
2. **立直后重复使用宣告时选定的牌。** 最后一局宣告时选择 6s；随后仍留有另一张 6s。13:37:31 再次出现弹窗时，旧锁存目标让自动操作又尝试 6s，但服务端记录的是刚摸入的 5m。该动作已有 unconfirmed-state-change，没有被记为成功。现在自身牌河增加后清除这次舍牌目标，保留本局“已宣告”标志，之后按新摸牌处理；不再复用旧目标。修复经过状态机回归，仍需下次自然游戏确认实际弹窗行为。
3. **红五万解码为普通五万。** physical=17 按红五万处理；离线导出同步三门红五映射、起手红牌别名、本场与 0x113 候选标记。
4. **不认识的分差形状被当作流局。** [-1000,-3000,4000,0] 含立直支付影响，不能仅凭该分差断定流局。现在无法识别时标记 unknown，保留 UI 推断属性；其他分差启发式也不替代网络结果确认。
